# Flutter MVVM Code Map

## 输出边界

- 默认只创建或更新 `docs/FEATURE_CODE_MAP.md`；除非用户明确要求，不修改 `AGENTS.md` 或业务代码。
- 使用项目相对路径和精确类名，不使用绝对路径、Markdown 文件链接或行号。
- 每个功能保留 1～3 个稳定入口和 2～5 个可直接用 `rg` 搜索的锚点。
- 不展开调用链、参数、状态流转、实现说明或完整文件清单。
- 代码与地图冲突时以代码为准；无法从源码确认的信息不要猜测。

使用以下结构，只列出项目中实际存在的全局入口：

```md
# 功能代码地图

## 全局入口

- <入口名称>：`<项目相对路径>`

## 功能索引

| 功能/别名 | 代码入口 | 检索锚点 |
|---|---|---|
```

## 工作流程

1. 确认当前目录包含 `pubspec.yaml` 和 `lib/`；否则停止并说明缺少的入口。
2. 已有地图时保留仍准确的人工分组和用语，只做必要更新。
3. 使用 `rg --files` 查找路由、页面、ViewModel、依赖装配、Repository、API、model、测试和产品预览。
4. 从路由、页面目录和预览注册表识别功能，再沿 import、构造器和依赖装配选取少量稳定锚点。
5. 从 l10n、页面名称和已有术语提取用户用语，并保留常用英文代码名；按业务功能而非技术分层组织条目。
6. 功能较多时可按业务域增加二级标题，但保持相同三列。
7. 校验每个路径存在，并用 `rg` 确认锚点拼写；修正或删除已失效条目。

完成后报告地图路径、覆盖的功能数量和无法从源码确认而省略的内容。

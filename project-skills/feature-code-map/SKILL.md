# 功能代码地图

## 写什么

- 默认只改 `docs/FEATURE_CODE_MAP.md`。修改 `AGENTS.md` 或业务代码需要用户明确要求。
- 按用户理解的功能组织条目，保留常用别名和英文代码名。
- 每个功能列 1～3 个稳定代码入口、2～5 个能用 `rg` 搜到的名称。
- 路径用项目相对路径，锚点用准确的类名或方法名。不用绝对路径、文件链接或行号。
- 不写调用链、参数、状态流转或详细实现，不列出所有相关文件。
- 地图与代码不一致时，以代码为准。源码无法确认的内容不要猜。

使用下面的格式。全局入口只写实际存在的文件：

```md
# 功能代码地图

## 全局入口

- <入口名称>：`<项目相对路径>`

## 功能索引

| 功能/别名 | 代码入口 | 检索锚点 |
|---|---|---|
```

## 怎么做

1. 确认当前目录有项目配置文件和源码目录。如果不是项目根目录，停止并说明缺少什么。
2. 先读已有地图。保留仍然准确的分组和用语。
3. 用 `rg --files` 查找入口、路由、页面、逻辑、数据、依赖组装、测试和预览文件。项目没有的层不要补造。
4. 从路由、页面和预览注册表找功能。沿 import、构造函数和依赖组装找到稳定入口。
5. 从界面文案、本地化文件和页面名称提取功能名称与别名。功能多时可以按业务分组，表格仍使用三列。
6. 检查路径是否存在，用 `rg` 核对锚点拼写。修正或删除失效条目。

完成后说明地图路径、功能数量，以及哪些内容因无法确认而省略。
